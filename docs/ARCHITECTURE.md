# 数据、迁移与性能边界

原生客户端通过 HTTPS Bearer API 连接 FastAPI。开发使用 SQLite WAL，正式环境要求 PostgreSQL + Redis。Alembic 管理显式迁移；数据库连接池、复合索引、稳定游标和原子计数减少列表查询成本。Redis 提供原子限流，故障时拒绝请求。

匿名凭证保存在系统安全存储，服务器只保存 HMAC 摘要。匿名不等于无法追踪：管理员能审查内容，托管网络日志可能包含 IP。凭证丢失无法恢复身份；卸载后保留凭证的行为取决于系统。身份删除清除在线关联内容并撤销令牌，备份清理周期须由运营方明确。

默认先审后发，客户端不能伪造审核状态；反馈按身份隔离。尚无图片上传、推送、跨设备身份同步或管理员多人权限体系。搜索当前为字符串匹配，较大数据量需增加 PostgreSQL 全文搜索并重新压测。

## 旧站迁移

原 Sites 网站与新服务数据库尚未连接。两者身份摘要不同，不能复制 ID 后声称身份已经继承。迁移前备份/导出旧库，确认字段及数量，在隔离环境验证内容归属和身份衔接。正式切换应冻结旧库写入、导入增量、核对完整性并保留回滚方案。本次没有执行生产数据迁移。

## 实测记录

2026-10-04，本机 Python 3.12 / SQLite，10,000 条帖子、200 次列表读取、8 个并发 TestClient：约 121.51 请求/秒，P50 64.15ms，P95 81.82ms，总耗时 1.646 秒。脚本在 `backend/scripts/benchmark.py`，仅允许专用 benchmark 数据库。

这不是正式服务器容量：未计入网络、TLS、PostgreSQL 和 Redis。不能声明比旧后端提高多少百分比。回归测试验证单页最多 3 次数据库查询及 feed 索引使用。上线后仍需真实数据压测。

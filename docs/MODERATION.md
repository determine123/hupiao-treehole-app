# 审核记录与作者说明（1.0.2）

管理员进入 `/admin`，审核时填写内部依据，可选填写“给作者的说明”。两者分别保存：内部依据只在管理员的“审核记录”栏目中显示；作者只能在应用“我的 → 我的审核记录与说明”查看自己的处理结果及作者说明。

后台记录按时间与编号分页，可按完整内容编号查询。修改查询输入后需要点击“查找记录”，继续翻页仍使用当前已提交的查询，避免混合不同内容的历史。

- `/admin/audit` 需要管理员密钥，返回内部记录和作者说明。
- `/moderation` 需要匿名身份凭据，只返回当前身份仍拥有的帖子及回复记录，不返回内部依据或举报信息。删除内容或身份后不再在作者列表中出现。
- 旧审核记录保留内部备注，作者说明为空，不将旧内部文字自动公开。
- 隐藏回复仅本人可用 `include_hidden=true` 查到；旧客户端默认查询保持原来的行为，其他人即使传入此参数也无法查看隐藏回复。
- 作者说明最多 300 字，管理员应避免填入举报人信息或隐私；手机号规则也对作者说明生效。

升级采用新增两列和索引的 Alembic 迁移，不改动现有身份与正文。迁移回归测试从旧版本建表、写入旧记录，再执行真实升级并检查结构差异；CI 同时在独立 PostgreSQL 测试 schema 验证，不接触线上数据。

数据库中的审计记录仍由管理员保留用于核对，当前没有自动清理期限。正式发布前需明确审计与备份的保留规则。

删除帖子时，其正文与下属回复的待处理举报在同一事务中标为 `resolved`；删除回复及匿名身份时也处理对应举报。举报记录仍保留，但这表示目标已被删除，并不代表管理员判定违规，也不会生成审核决定。其他内容的举报不受影响。

管理员待处理列表在截取 100 条之前排除目标已不存在的旧举报，避免历史遗留记录挤占有效举报。旧记录不会因为读取列表被修改。此修复仅涉及后端，无需重新安装 APK 或迁移数据库。

源码、数据库迁移和安装包发布状态分别记录在 DEPLOYED.md 与下载说明；在实际部署和签名构建成功前，不视为手机已经可用。
